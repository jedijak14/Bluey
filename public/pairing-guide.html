One PC. A little company everywhere.

Pairing connects a device directly to your Windows engine. Vercel serves the interface; it does not run your PC, generate valid codes, or relay your requests.

Which button do I use?

  • Enter pairing code / Pair this device: enter the PC endpoint and six-digit code. This browser becomes a companion, with no desktop administration privileges.
  • Connected devices → Pair my Android: connect as the desktop administrator in Settings, then generate a code for another device. Never enter your desktop token in the pairing-code field.

Android APK: ordinary private Wi-Fi

  1. Configure the Windows app’s Python engine. Enable BLUEY_LAN=1 before launching the Windows app, or run python -m backend.server --lan from the source checkout.
  2. Keep both devices on the same trusted private network. Allow Python’s TCP port 8765 in Windows Firewall for private networks only.
  3. Generate a code in the Windows workspace’s Connected devices screen.
  4. In the Android APK, enter the PC’s Wi-Fi address (for example 192.168.1.10:8765) and the code. Do not enter localhost or the Vercel website address.

Download the published Android preview APK. The APK is debug-signed and needs the Windows engine; it is not a standalone AI service.

Vercel website: a secure route to your PC

An HTTPS website cannot reliably call an ordinary HTTP LAN engine. You need a trusted HTTPS/WSS endpoint reachable from this device over your private network or VPN. A six-digit code alone cannot locate or connect to a PC.

  1. Configure a private HTTPS reverse proxy to the running Windows engine at http://127.0.0.1:8765. It must forward /api/* and WebSocket upgrades for /api/ws. Use a certificate trusted by each device and matching the endpoint’s hostname. Keep the endpoint restricted to your private network or VPN; do not use a public tunnel or port-forward the engine.
  2. Before starting the Windows engine/app, explicitly allow the exact website origin. For this deployment, in PowerShell: 
    $env:BLUEY_LAN = "1"
$env:BLUEY_ALLOWED_ORIGINS = "https://bluey-plum.vercel.app"
# Now launch Bluey from this same environment.
    For local source development add the exact Vite preview origin as a comma-separated value. Do not use a wildcard. The backend does not read .env files automatically.
  3. To generate a code on the website: open Settings, enter the secure PC endpoint and desktop token from the engine startup log, then Save & connect. Only enter that token into a website you trust. It grants desktop-level engine access and stays in memory.
  4. To redeem a code: choose Enter pairing code, enter the same secure endpoint and a fresh code from Windows, then Pair with Windows. Browser/private-network permission prompts must be allowed for this trusted PC.

If you do not already have private HTTPS configured, use the Windows app and Android APK rather than weakening browser security. A self-signed certificate is not sufficient unless it has been properly trusted on every device. The website does not provision certificates, a VPN, or a cloud relay.

Live codes and device status

Each code lasts two minutes and works once. While Connected devices is open and connected, the countdown updates every second and the paired-device list refreshes every two seconds. An unused expired code is replaced automatically. Refresh stops after a device pairs, when you leave the page, or if an error occurs. Generate a new code to retry. Keep only one code-generation screen active per PC to avoid replacing another screen’s code.

“Paired” means authorized for this engine session, not necessarily currently online. The companion shows the live WebSocket connection status separately. Restarting the backend invalidates its codes and device credentials; restarting the companion requires pairing again.

If it still fails

  • Invalid or expired code: get the latest code from the same engine endpoint. Used codes cannot be redeemed again.
  • Too many attempts: wait a minute before trying again.
  • Cannot reach PC: check endpoint, private network/VPN, certificate, firewall, and exact allowed origin. Never disable browser security or make the engine publicly accessible.
  • Connected, but no AI reply: configure your local model. Voice additionally needs Whisper and Piper models on Windows; pairing does not install them.
